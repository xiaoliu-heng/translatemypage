TranslateMyPage 0.2.1 — review instructions (draft; not submitted)

Single purpose: AI webpage bilingual and selected-text translation.
Free, MIT-licensed source: https://github.com/xiaoliu-heng/translatemypage

Install only the extension. There is no Native Messaging host, local HTTP listener, OS keychain bridge or Node.js runtime dependency.

1. Click the extension toolbar button, then Continue with ChatGPT to open its visible Translation Session tab.
2. Click Continue with ChatGPT in that tab; sign in and consent on OpenAI's official page using an eligible personal account. No shared developer credentials are provided.
3. Authorization returns to http://127.0.0.1:1455/auth/callback. With no local listener, a browser connection error is expected. Copy the complete URL from the address bar into the session tab's masked callback field. Submit within five minutes. Do not put the callback URL or any token in a review transcript.
4. The extension validates state, one-time consumption, exact redirect, issued client binding, PKCE and the signed ID-token claims. Plan availability uses token-response scopes rather than login success alone.
5. Confirm the plan usage notice, select an available model, keep the session tab open, and return to a normal HTTPS article. Open the toolbar popup and start translation; confirm content sharing on first use.
6. Verify bilingual text, original typography and links, selected-text loading and dialogue, draggable pet, stop/restore and explicit retry.
7. Close the session tab: requests stop and local credentials are discarded. Restart the session and verify fresh authorization. Sign out explicitly to attempt remote revocation. A failed revocation is disclosed with a link to ChatGPT settings.
8. Test simultaneous session pages, cancelled authorization, wrong/stale callbacks, account switching, quota limits and worker disconnection. Unknown inference results must not be automatically replayed.

API-key route:
1. In the session tab, choose "使用 OpenAI API key" and enter your own key. No shared developer key is provided. This configures an unverified session-only credential; model and translation requests validate its permissions.
2. Explicitly select a Responses-compatible text model. The API catalog may also contain incompatible non-text models; the extension does not automatically choose a model for API keys.
3. Start webpage or selected-text translation from the toolbar popup and confirm content sharing. Verify POST /v1/responses with streaming and store:false, separate API billing, safe invalid-key/quota messages and no fallback to ChatGPT billing.
4. Disconnect and refresh the session to verify the key is forgotten, without calling OAuth revocation or revoking the platform key. Verify account switching and isolated model settings/cache.

Only activeTab, scripting and storage are requested, with host access limited to auth.openai.com and api.openai.com. No browser-history API, broad website permission, remote executable code or developer inference proxy is used. OAuth tokens and API keys stay in the session page's memory; API keys never pass through background/page message routing. Nonsecret registration identifiers, API connection digests and preferences use chrome.storage.local; account-isolated translation cache uses IndexedDB.

The documented OpenAI OAuth flow describes a loopback listener. This project instead accepts the callback manually. Isolated Chromium checks with synthetic credentials/responses cover both modes but do not establish real provider compatibility or paid inference. Verify real OAuth, API-key translation and billing in the installed extension before submitting this draft with current screenshots.
