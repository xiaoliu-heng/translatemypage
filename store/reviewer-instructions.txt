TranslateMyPage 0.2.1 — review instructions (draft; not submitted)

Single purpose: AI webpage bilingual and selected-text translation.
Free, MIT-licensed source: https://github.com/xiaoliu-heng/translatemypage

Install only the extension. There is no Native Messaging host, local HTTP listener, OS keychain bridge or Node.js runtime dependency.

1. Click the extension toolbar button, then Continue with ChatGPT to open its visible Translation Session tab.
2. Click Continue with ChatGPT in that tab; sign in and consent on OpenAI's official page using an eligible personal account. No shared developer credentials are provided.
3. Authorization returns to http://127.0.0.1:1455/auth/callback. With no local listener, a browser connection error is expected. Copy the complete URL from the address bar into the session tab's masked callback field. Submit within five minutes. Do not put the callback URL or any token in a review transcript.
4. The extension validates state, one-time consumption, exact redirect, issued client binding, PKCE and the signed ID-token claims. Plan availability uses token-response scopes rather than login success alone.
5. Confirm the plan usage notice, select a model, keep the session open, and return to a normal HTTPS article. The page logo appears automatically but translation is initially off. Click it and confirm the displayed recipient before sharing content.
6. Verify bilingual text, original typography and links, selected-text dialogue, draggable logo, stop/restore and explicit retry. Test mixed-language paragraphs: only content not already in the target language should show a translation; identical output is hidden.
7. Close the ChatGPT session: OAuth credentials are discarded and fresh authorization is required. Explicit sign-out attempts remote revocation; failure is disclosed with a ChatGPT settings link. API keys follow the persistent behavior below.
8. Test simultaneous session pages, cancelled authorization, wrong/stale callbacks, account switching, quota limits and worker disconnection. Unknown inference results must not be automatically replayed.

API-key route:
1. In the session tab, choose "设置 API key 与服务商". Enter your own key and full Responses API base URL (default https://api.openai.com/v1); allow the requested provider host. No shared developer key is provided. The key and URL persist unencrypted in extension-origin IndexedDB. Save clears the input and automatically loads models, sending the key to the configured provider; saving alone does not verify it.
2. Explicitly select a Responses-compatible text model. The catalog may also contain incompatible non-text models. Custom endpoints must provide GET <base>/models and POST <base>/responses. HTTP is allowed with an explicit plaintext warning.
3. Click the page logo or use the toolbar, confirm the exact recipient origin and separate API billing, and verify streaming Responses with store:false. Changing origin requires consent again. Test safe invalid-key/quota errors and no fallback to ChatGPT billing.
4. Close/reopen or refresh the session and verify saved key, URL and explicit model restoration. Selecting ChatGPT must not silently reactivate API billing. "删除已保存的密钥" permanently removes that local connection; reopening must not restore it. This does not revoke the provider's platform key. Verify independent settings/cache for different key-and-address pairs.

The extension requests activeTab, scripting and storage. Static HTTP/HTTPS main-document content scripts display the logo on ordinary pages by default, requiring broad website content-script access; they do not scan article text or submit translation before activation. Official network hosts are auth.openai.com and api.openai.com; custom API network access is requested per host through optional HTTP/HTTPS permissions. Chrome host permissions cover all ports, while content consent is bound to the exact origin. No browser-history API, remote executable code or developer inference proxy is used. OAuth tokens stay only in memory; API keys persist unencrypted in extension IndexedDB and never pass through background/page routing, chrome.storage.local or logs. Cache clearing does not delete keys.

The documented OpenAI OAuth flow describes a loopback listener. This project instead accepts the callback manually. Isolated Chromium checks with synthetic credentials/responses cover both modes but do not establish real provider compatibility or paid inference. Verify real OAuth, API-key translation and billing in the installed extension before submitting this draft with current screenshots.
